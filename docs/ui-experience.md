# Tenant experience redesign

This frontend-only increment builds on approved-rule PR #21. Angular/Rails API contracts, authentication, authorization and lifecycle policies remain unchanged. It is a visual/interaction redesign, not a production-readiness claim.

## Design

A consistent navy/coral workspace, real signed-in role, active navigation, page titles and a responsive sidebar replace the scaffold header and prototype badge. Directory rows use actual authorized API records and pagination, contact counts, primary contacts, monthly subscription display and text-labelled status badges. No invented platform metrics, customers, dates or activity are shipped.

Company overview groups company information, contacts/owner, branding and commercial settings. User-facing asset/admin UUIDs and implementation explanations are removed. Owner/reference labels come from existing reference data, with honest fallbacks when unavailable. Permissions still come from the backend.

The reusable form is ordered Company → Contacts → Branding → Subscription, with same-page section navigation, contextual payment/discount fields, a sticky save area and live branding preview. No field is dropped from persistence. Technical validation paths become readable field labels; existing validation and unsaved-draft safeguards remain. Branding preview chooses black/white text contrast for saved hex colours.

Sign-in, reference options, saved preview, empty/error/loading states and lifecycle confirmations share the design. No placeholder controls, mock dashboard statistics, registration or password-reset service is introduced. Contact entry still does not grant user access.

## Tenant workspace usability increment

Current local work builds on the enterprise-polished interface. Tenant details now expose a lazy-loaded activity timeline backed by existing immutable Rails audit records, ordered newest first with server pagination. Only events for a tenant readable by the signed-in administrator are returned. This is recorded history, not fabricated dashboard activity. Event actor identities, request IDs, old/new values and arbitrary metadata are deliberately not exposed. Existing records only capture changed top-level field names, so the timeline does not claim a detailed before/after comparison.

Directory search, status, page and row count survive navigation to details and back within the signed-in application. State lives only in Angular service memory, not localStorage; a full browser reload resets it. Rows per page uses existing Rails per_page support (20/50/100). No new search semantics, sorting or bulk operations. Tenant details display a saved contact phone when present. The design reuses existing controls/tokens, including mobile layouts and keyboard focus.

A real restart issue was found while Docker was stopped: source-mounted backend/tmp/pids/server.pid could outlive the Rails process. Compose now puts the PID in /tmp/cpq-rails.pid inside the backend container, clearing that exact container-local runtime file before starting Rails. The source file and all databases remain untouched. A stale session-check notice now clears after successful authentication, with a regression test.

No migrations, dependency changes, cloud resources or new account roles. Super Admin and assigned CPQ Admin read boundaries remain enforced by the backend; tenant-user invitations, billing engines and custom permissions have not been added. Preview and start/stop commands remain the local integration commands above.

The two pre-existing shell/form stylesheet advisories remain below the error limits. Real Devise browser login and existing tenant activity retrieval passed: 13 persisted events, newest first. Search Local and 50 rows per page were preserved after opening details and returning. Activity reflow passed 375/768/1280/1440px and directory footer at 375px, without horizontal overflow.
